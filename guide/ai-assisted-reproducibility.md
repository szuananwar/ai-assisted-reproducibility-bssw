# AI-Assisted Reproducibility in Scientific Software

Scientific software increasingly depends on complex workflows that combine source code, datasets, computational environments, machine learning models, and high-performance computing resources. As these workflows become more advanced, they also become more difficult to reproduce. A research result may depend not only on the code itself, but also on library versions, compiler settings, hardware configuration, random seeds, workflow scripts, and experiment tracking practices.

AI-assisted reproducibility provides a new way to support researchers and software teams by helping them identify missing reproducibility components and recommending practical improvements. Instead of relying only on manual checklists, an AI-assisted system can examine a project repository and detect whether key files are present, such as a README, environment file, test directory, container recipe, workflow documentation, and experiment tracking logs.

For example, an AI-assisted reproducibility checker may review a scientific AI project and report that the repository includes source code and a dataset, but lacks a container file, automated tests, and experiment tracking. The system can then recommend specific actions, such as adding a requirements.txt or spack.yaml file, creating a simple tests/ directory, using MLflow to track model parameters, or documenting how to reproduce the results from the command line.

This approach is especially valuable for AI-enabled HPC workflows, where reproducibility challenges are often caused by differences in software stacks, modules, dependencies, and execution environments. Tools such as Spack, BuildTest, containers, and MLflow can support reproducible workflows, but researchers may not always know when or how to use them. AI can serve as a guide that connects best practices to the specific needs of a project.

The goal is not to replace human judgment. Instead, AI-assisted reproducibility should support researchers by making reproducibility problems more visible, lowering the barrier to adopting best practices, and helping teams improve their software over time. This project introduces an initial framework for evaluating reproducibility and generating recommendations that can be expanded into a more advanced self-healing scientific workflow system.
